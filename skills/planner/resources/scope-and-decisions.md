# Scope and decisions

Use when requirements, ownership, or boundaries are ambiguous.

- Separate what the user wants from how to implement it.
- Capture in scope, out of scope, success criteria, constraints, assumptions, and open decisions.
- Use requirement deltas when behavior changes: ADDED, MODIFIED, REMOVED, RENAMED.
- Ask only questions the user must own: product behavior, compatibility promise, risk appetite, approval, budget, or irreversible tradeoff.
- For each open question, state why it blocks planning and recommend the default answer.
- If ambiguity affects only a later slice, mark that slice `blocked` and continue planning independent slices.
